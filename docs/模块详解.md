## 一、总体架构

```
浏览器 (Vue3 + Socket.IO Client)
    │  HTTP /api/*  +  WebSocket /socket.io/*
    ▼
┌──────────────────────────┐
│  frontend 容器 (Nginx)    │  静态托管 + /api、/socket.io 反向代理
└───────────┬──────────────┘
            ▼
┌──────────────────────────┐
│  backend (Express +       │
│  Socket.IO)               │
│  ├─ routes   REST 接口    │
│  ├─ socket   实时事件     │
│  ├─ game     游戏引擎+AI  │
│  └─ services 统计/RAG/QA  │
└──────┬───────────┬────────┘
       ▼           ▼
   ┌────────┐  ┌────────┐
   │ MySQL  │  │ Redis  │
   │ 持久化 │  │ 缓存   │
   └────────┘  └────────┘
```

技术栈：后端 Node.js + Express + Socket.IO + MySQL + Redis + node-cache + LangChain；前端 Vue 3 + Vite + Pinia + Vue Router + Axios。

## 二、后端模块

### 2.1 入口与配置

#### `src/app.js` — 应用入口

整个服务的组装点，职责：

- **环境校验**：`validateEnv()` 启动时强制校验 `JWT_SECRET`（≥32 字符），生产环境额外校验 DB 连接、`LLM_CONFIG_ENCRYPTION_KEY`、`LLM_ALLOWED_HOSTS`，缺失直接 `process.exit(1)`。
- **中间件**：CORS（白名单 + credentials）、`express-rate-limit`（auth 20 次/分钟，通用 API 100 次/分钟）、body 限 1MB、统一 JSON 头。
- **路由挂载**：`/api/auth`、`/api/ai-agents`、`/api/replays`、`/api/stats`、`/api/settings`，以及内联的 `/api/lobby-stats`、`/api/rooms`、`/api/room/:code`、`/api/health`、`/api/ready`。
- **健康检查**：`/api/health` 组合 DB + Redis + 在线人数 + 房间数，Redis 不可用标 `degraded`，DB 挂了标 `unhealthy`（503）。
- **错误处理**：404 兜底 + 全局错误中间件（`AppError` 取状态码，413/403/CORS 特判，生产环境不返回 stack）。
- **启动/关闭**：`initDB → aiAgentManager.init → initRedis → syncAllUsersToRedis → listen`；SIGINT/SIGTERM 优雅关闭 Redis；`unhandledRejection`/`uncaughtException` 直接退出。

#### `src/config/db.js` — 数据库与迁移

- 基于 `mysql2/promise` 连接池（`connectionLimit: 10`）。
- **自研轻量迁移系统**：`schema_version` 表记录已应用版本，`MIGRATIONS` 数组按 `version` 递增，每条迁移在独立事务里执行，失败回滚。当前共 9 个版本（建表、补列、积分规则、refresh token 表等）。
- `initDB()` 先以无库连接 `CREATE DATABASE IF NOT EXISTS`，再跑迁移，实现「首次启动自动建库建表」。

#### `src/config/redis.js` — Redis 连接管理

- 单例 `client`，`getRedisClient()` 在未就绪时返回 `null`（调用方据此降级）。
- 支持 `REDIS_DISABLED=true` 完全关闭、`REDIS_RECONNECT_RETRIES` 重试上限、退避重连。
- 初始连接失败不致命，回退「仅内存缓存」，服务照常启动。
- `getRedisStatus()` 供健康检查，URL 密码脱敏。

#### `src/config/llmConfig.js` — 大模型配置与实例构建

- 系统**不内置任何默认 Key**，唯一的 LLM 来源是用户「设置」页绑定的 Key。
- `buildModel()` 按 `apiKey/apiUrl/modelName/temperature/maxTokens` 的 SHA-256 签名缓存 `ChatOpenAI` 实例，避免重复建。
- `validateApiUrl()` 做 **SSRF 防护**：拒绝非 http/https、含认证信息、指向 localhost/内网/链路本地地址的 URL，并校验域名在 `LLM_ALLOWED_HOSTS` 白名单内。
- `maskKey()` 打码展示 Key。

### 2.2 数据模型 models

| 文件 | 对应表 | 职责 |
|---|---|---|
| `User.js` | `users` | 注册/登录/资料、积分增减、LLM 配置读写（Key 加密存储） |
| `GameRecord.js` | `game_records` / `game_players` | 对局记录、玩家战绩、按真实记录重算战绩 |
| `AIAgent.js` | `ai_agents` | AI 智能体 CRUD（JSON 字段序列化） |
| `RefreshToken.js` | `refresh_tokens` | refresh token 哈希存储、撤销、单设备登录 |

要点：

- **积分规则**：积分恒等于累计胜场数（`score = total_wins`）。`User.updateScore` 胜局 `score+1,total_wins+1`，败局仅 `total_games+1,total_losses+1`。
- **一致性修复**：`User.recalcStatsFromGamePlayers` 用 `game_players` 真实记录覆盖 `users` 表统计；`GameRecord.calcRealStatsForUser` 从 `game_players` 聚合真实战绩。
- **LLM Key 加密**：`api_key` 列存 AES-256-GCM 密文（见 `utils/secretCrypto.js`），读取时解密。
- **Refresh Token**：只存 SHA-256 哈希，不存明文；`revokeAllForUser` 实现「同一账号多设备登录踢出旧会话」。

### 2.3 中间件 middleware

#### `src/middleware/auth.js`

- 校验 `Authorization: Bearer <token>`，用 `jsonwebtoken.verify` 解析。
- **拒绝 refresh token 冒充 access token**：`decoded.type === 'refresh'` 时返回 401。
- 通过后把 `req.user = decoded`（含 id/username）交给路由。

### 2.4 路由 routes

| 路由 | 前缀 | 主要接口 |
|---|---|---|
| `auth.js` | `/api/auth` | `register` / `login` / `me`(GET/PUT) / `refresh` / `logout` |
| `aiAgentRoutes.js` | `/api/ai-agents` | AI 智能体 CRUD（管理员/所有者权限） |
| `replayRoutes.js` | `/api/replays` | `GET /:id` 获取复盘（校验归属） |
| `stats.js` | `/api/stats` | `me` / `history` / `leaderboard` / `sync` / `clear` / `ai` |
| `settings.js` | `/api/settings` | LLM 配置 `GET/PUT/DELETE /llm`、`POST /llm/test` |

要点：

- **auth.js**：用户名「字母/数字/下划线/中文 2-20 位」、密码「≥6 位且含字母和数字」校验；登录/注册都 `revokeAllForUser` 实现单设备登录；`/refresh` 做 token 轮换 + 复用检测（已撤销 token 被重放视为泄露，撤销该用户全部会话）。
- **aiAgentRoutes.js**：`canModify` 权限——管理员可改任意、创建者只能改自己的、内置 AI（`ownerId===null`）仅管理员可动。
- **stats.js**：`ADMIN_USER_IDS` 环境变量白名单，未配置时管理接口返回 501；所有 stats 响应禁止 HTTP 缓存。
- **settings.js**：`/llm/test` 用表单值优先、已存值兜底，`buildModel` 后 `invoke('请只回复两个字：OK')` 实测连通性并返回延迟。

### 2.5 服务层 services

#### `services/statsService.js` — 积分与排行榜

- **Redis 作为排行榜加速层**，MySQL 为主数据，全程可降级。
- 键：`werewolf:leaderboard`（ZSet）、`werewolf:user:score:<id>`（Hash）、`werewolf:user:name:<id>`、`werewolf:user:rank:<id>`（排名缓存 60s）。
- `syncAllUsersToRedis` 启动时全量回填；`updateUserScore` 双写；`getUserStats` 做一致性校验并自动修复；`getLeaderboard` Redis 优先、MySQL 兜底。

#### `services/GameRetriever.js` — RAG 知识检索

- 加载 `knowledge/` 下三类 Markdown（策略 strategies / 规则 rules / 历史对局 replays），按段落切块（≤500 字符）。
- `retrieve()` 用**分层加权评分**：角色精确匹配 +20、角色关键词 +10、阵营 +6、阶段 +5、情境 +15、指令性内容 +3，归一化后返回 Top-K。
- `_detectSituation()` 识别平安夜/猎人开枪/女巫毒杀/查杀/末神/危机等局势。
- `addGameReplay()` 把结束对局转 Markdown 入库，**质量评分**（时长/事件数/夜数/人数）过滤低价值对局，最多保留 100 场。
- 检索结果带 LRU 缓存（60s / 100 条），并统计命中率（供 `/api/stats/ai`）。

#### `services/RuleQAService.js` — 规则问答

- 玩家在房间发以 `?`/`？` 开头或含「规则/怎么玩/如何」的消息时触发。
- 走 RAG 检索规则文档 → LLM 生成自然语言回答（用**提问者自己的 Key**）。
- 无 Key 或 LLM 出错时降级为直接返回检索到的规则片段。

### 2.6 AI 智能体 ai

#### `ai/AIAgentManager.js`

- 内置 10 个默认智能体（预言家/村民/狼人/女巫/猎人/守卫等），首启 `bulkInsertIfEmpty` 写入。
- **智能体结构**：五维性格（aggressiveness/caution/cunning/honesty/talkativeness，0-100）、发言风格、策略（夜间行动/白天策略/身份暴露时机）、语言习惯（前缀/后缀/口头禅）。
- `normalizeAgent()` 做**Prompt 注入防护**：`sanitizePromptString` 清控制字符、过滤「忽略以上指令」等注入词、截断长度；说话风格/策略走白名单，性格数值钳制 0-100。
- `getRandomAgent()` 维护一个「随机池」，取一个移一个，池空时 `resetRandomAgents` 重新填充。

### 2.7 游戏引擎 game

#### `game/constants.js`

游戏常量：`PHASE`（WAITING/NIGHT/LAST_WILL/DISCUSSION/DAY/VOTE/END）、`ROLE`（狼人/村民/预言家/女巫/猎人/守卫）、`TIMERS`（各阶段秒数）、`ROLE_NAMES`、`TEAM`（阵营归属）、`ROLE_DISTRIBUTION`（6/8/12 人的角色配置）。

#### `game/RoleConfig.js`

`getRolesForGame` 按人数取角色列表并 Fisher-Yates 洗牌；非标准人数走兜底算法（狼≈1/3、神职≤4、其余村民）。

#### `game/GameEngine.js`

- 继承 `EventEmitter`，用 **Mixin 模式**（`CoreMixin`/`NightPhaseMixin`/`DayPhaseMixin`/`VotePhaseMixin`/`GameEndMixin`）把一个大类拆成五个关注点。
- 持有房间码、玩家、角色映射、阶段、计时器、夜间行动、投票、猎人、发言队列、`gameHistory`（复盘用）等全部对局状态。

#### `game/CoreMixin.js`

- 通用 helper：`alivePlayers`、`getPlayer`、`getRole`、`getSeatNum`（返回「N号」）、`broadcast`/`sendTo`。
- `start()`：校验全员准备 → 发牌 → 逐个通知角色与座位 → 广播开始 → 3 秒后进第一夜。

#### `game/NightPhaseMixin.js`

- `startNight`/`runNightSequence`：按 **守卫 → 狼人 → 预言家 → 女巫** 顺序推进子阶段，整体有 150s 兜底超时。
- `submitNightAction`：做角色-行动白名单、存活/目标合法性、女巫药水一次性、守卫不可连续守同人等校验，并把行动写入 `gameHistory`。
- `resolveNight`：结算狼刀（多数决）、守卫守护、女巫解救（**同守同救仍死**）、女巫毒杀 → 生成死亡名单 → 触发猎人开枪 → 检查胜负 → 进入白天。
- 狼人击杀有 `_broadcastWerewolfVoteState` 实时同步队友投票状态。

#### `game/DayPhaseMixin.js`

- 白天流程：**死亡遗言（LAST_WILL）→ 自由讨论（DISCUSSION）→ 轮流发言（DAY）→ 投票（VOTE）**。
- AI 在自由讨论阶段并行发言（随机 2-8s 首条 + 15-30s 第二条，30% 概率插话），轮流发言阶段按序发言。
- `_ensureMessageLength` 按 `talkativeness` 性格调整发言长度，短了补角色化扩展句，长了截断。

#### `game/VotePhaseMixin.js`

- `startVote` 等 AI 先投 → 广播 → 计时 → `resolveVote` 结算。
- **平票 PK**：`_startPKVote` 限制只能投 PK 候选，最多一轮，二轮仍平票则无人出局进夜。

#### `game/GameEndMixin.js`

- `checkWinCondition`：狼全灭 → 村民胜；狼数 ≥ 非狼数 → 狼胜。
- `endGame`：广播 `game_over` + 发出 `__game_result`（持久化用）+ `__game_replay`（房间内复盘卡片）。
- `generateReplayMessage` 组装身份揭晓 + 胜负名单 + 按夜分组的复盘事件。

#### `game/AIGameHandler.js`（最大、最核心的 AI 模块）

- **决策入口**：`handlePhaseChange` 按阶段分派到夜间/投票/白天逻辑。
- **并发控制**：`pLimit(5)` 限制并行 LLM 调用，避免同时大量请求。
- **夜间决策** `_decideNightAction`：RAG 检索策略 + 智能体策略 + `StructuredOutputParser` 强制结构化输出（action/targetId/reasoning），校验目标合法性，失败回退 `_getFallbackNightAction`（随机/按角色）。
- **投票决策** `_decideVote`：同理，LLM 结构化输出 + RAG + 兜底（好人阵营优先投预言家验出的狼、被多次怀疑者）。
- **发言生成** `_generateChatMessage`：拼接角色/阵营/存活/死亡/最近聊天/游戏事件/性格/发言风格/情绪（含「被点名要回应」「队友刚死」等）→ 大段「口语化要求」Prompt（禁止书面语、给正反示例）→ 超时 12s 兜底。
- **无 LLM 时的模板发言**：`_getFallbackChatMessage` 按角色（预言家/狼人/女巫/守卫/猎人/村民）用正则解析聊天上下文（谁跳了身份、谁被怀疑）生成符合人设的模板发言，状态按 roomCode 隔离。
- 决策日志保留最近 100 条，供 `/api/stats/ai` 查看。

#### `game/ReplayAnalyzer.js` — 赛后复盘分析

- 规则版：统计投票关系图、有效投狼次数（MVP）、转折点、时间线。
- LLM 版（有模型时）：把精简对局喂给模型生成 verdict/highlights/mvp，8s 超时，解析失败回退规则版。

### 2.8 实时通信 socket

#### `socket/index.js` — Socket.IO 入口

- **连接认证中间件**：从 `socket.handshake.auth.token` 取 JWT 验证，失败 `AUTH_REQUIRED`/`AUTH_FAILED`。
- 连接后 `kickOldSocket` 踢掉同账号旧连接（单设备登录），并绑定所有事件：`create_room`/`join_room`/`leave_room`/`player_ready`/`add_ai_player`/`remove_ai_player`/`start_game`/`night_action`/`hunter_shoot`/`vote`/`skip_day`/`chat`/`rule_qa`/`next_speaker`/`skip_speaking`/`reset_game`/`disconnect`。
- 游戏类事件统一走 `socketValidators` 校验（房间归属、阶段、存活、房主）。

#### `socket/roomHandler.js` — 房间管理

- 房间码生成（排除易混淆字符 I/O/0/1），6 位、冲突重试 50 次。
- `createRoom`/`joinRoom`/`leaveRoom`/`toggleReady`/`addChat`，座位分配 `findEmptySeat`。
- **AI 玩家增删**（仅房主、仅 WAITING 阶段）：`createAIPlayer` 从 `AIAgentManager` 取智能体，生成 `ai_xxx` 的伪 socketId。
- **聊天权限**：按阶段限制（夜间/投票/结束禁言、遗言只死者、轮流发言只当前发言者），限频 3 条/秒。
- **断线重连**：游戏进行中掉线保留 60s（超时判死并检查胜负），等待室掉线 30s 后移除；`joinRoom` 对重连玩家做 socketId 迁移 + 角色映射恢复 + 补齐当前阶段状态。
- **房间销毁**：房主离开、或只剩 AI 时销毁。

#### `socket/gameHandler.js` — 游戏事件处理

- `startGame`：校验房主与人数，构造 `GameEngine` 存入 `gameCache`，`emit` 回调里拦截 `__game_result`/`__game_replay`/`chat_message`/`phase_change` 做落库/聊天缓存/AI 阶段通知。
- `handleNightAction`/`handleVote`/`handleHunterShoot`：把 socket 事件转成 `game.submit*` 调用，做角色-行动白名单与阶段校验。
- `handleGameResult`：写 `game_records` + `game_players` + 更新积分（重试 3 次），把对局投喂 RAG 知识库；**全部失败则 `lPush` 到 Redis 恢复队列** `werewolf:failed_games`。
- `resetGame`：结束后把房间恢复为可再开一局。

## 三、前端模块

### 3.1 入口与路由

#### `src/main.js`

创建应用、注册 Pinia、注册 Router、读取 localStorage 主题设置到 `<html data-theme>`，挂载 `#app`。

#### `src/App.vue`

根组件：顶部导航（大厅/AI工坊/战绩/设置）、主题切换按钮、用户名入口；全局挂 `Toast` 与 `ConfirmDialog`。房间/游戏页隐藏 header、禁用外层滚动。

#### `src/router/index.js`

- 9 条路由，除 login 外均 `requiresAuth`，组件**懒加载**。
- `isTokenExpired`：前端直接解析 JWT payload 的 `exp`（base64url 解码），提前 30s 判过期。
- `beforeEach` 守卫：access 过期但有 refresh token 时先 `refreshAccessToken()` 无感续期；有保存的房间码则自动回房。

### 3.2 网络层 api / socket

#### `src/api.js`

- axios 实例，`baseURL: /api`，请求拦截器自动附 `Authorization: Bearer <token>`。
- 响应拦截器：401 且非 auth 接口时，用 refresh token 换新 token 后**重试原请求**（`_retry` 防死循环）。

#### `src/socket.js`

- Socket.IO 客户端，`autoConnect: false` 手动连，`transports: ['websocket','polling']`。
- 自定义 `socket.connect()` 每次携带最新 access token。
- 显式重连参数（最多 10 次、1s 起、上限 10s）；`connect_error` 时先刷新 token 再重连，失败跳登录。
- 监听 `force_logout`（被别的设备挤下线）清 token 跳登录；`authenticate()` 返回 Promise 并带 15s 超时兜底。

## 四、核心数据流

### 一局游戏的完整链路

```
房主 create_room ──▶ roomHandler 建房间(roomCache)
玩家 join_room ──▶ 加入房间、分配座位
房主 add_ai_player ──▶ AIAgentManager 取智能体 → room.players
房主 start_game ──▶ gameHandler 建 GameEngine(gameCache) → 发牌
   │
   ├─ NIGHT  NightPhaseMixin 逐角色行动（AI 走 AIGameHandler LLM/RAG/兜底）
   ├─ 猎人开枪 / 女巫毒杀 / 同守同救 结算
   ├─ LAST_WILL 死者遗言（AI 由 DayPhaseMixin 触发）
   ├─ DISCUSSION 自由讨论（AI 并行发言）
   ├─ DAY 轮流发言
   ├─ VOTE 投票（平票 PK）
   └─ END  GameEndMixin 判胜 → emit __game_result
            └─▶ gameHandler.handleGameResult
                  ├─ GameRecord.create + addPlayer
                  ├─ statsService.updateUserScore（MySQL 主 + Redis 缓）
                  ├─ analyzeReplay（规则 + LLM）
                  └─ gameRetriever.addGameReplay（RAG 入库）
```

### 缓存读写关系

- **实时状态**（房间/对局/连接）：`node-cache` 进程内存为唯一读源，Redis 异步镜像（跨实例/重启容灾）。
- **排行榜**：Redis 为读加速层（ZSet），MySQL 为主数据，读失败自动降级 MySQL。

## 五、关键设计要点

1. **可降级**：Redis、LLM 全程 `if (可用)` + `try-catch`，Redis 挂了走内存、LLM 挂了走模板兜底，不影响主流程。
2. **双 token 认证**：短时 JWT access（15m）+ 不透明 refresh（7 天，库存哈希），轮换 + 滑动续期 + 复用检测 + 单设备登录。
3. **安全防护**：CORS 白名单、限频、body 限流、SSRF 校验、Prompt 注入过滤、Key 加密存储、refresh token 只存哈希。
4. **Mixin 拆分**：游戏引擎用五块 Mixin 组织，把「阶段流转/夜间结算/白天发言/投票/胜负」解耦。
5. **RAG 驱动 AI**：AI 决策与发言都注入知识库检索结果，且支持用户级 LLM Key（房主 Key 供 AI 使用，提问者 Key 供规则问答）。
6. **重连健壮性**：游戏中断线保留 60s 宽限，重连时迁移 socketId、恢复角色映射、补齐当前阶段 UI 状态。
